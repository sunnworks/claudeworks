# 농인용 건강검진 수어 사전문진 데모

성인 국가건강검진 사전문진을 **수어영상과 쉬운 한국어**로 확인하고 직접 답하는 작동형 데모입니다.
화면 시안이 아니라 **분기 규칙, 점수 계산, 답변 검토, 안전 플로우, 개인정보 안전선**이 실제로 동작합니다.

구현 근거: `농인용 건강검진 수어문진 서비스 기획설계서 v1.0` (부록 A~I) 및 `Claude Code 개발 지시문`.

> 시연용 데모입니다. 진단하지 않으며 병원이나 국민건강보험공단으로 전송하지 않습니다.
> 답변은 브라우저 메모리에만 있고 새로고침하면 사라집니다.

## 1. 실행 방법

### (1) 개발자 PC — Node.js 20 이상

```bash
cd checkup
npm install
npm run dev            # http://localhost:5173
npm run dev:lan        # 같은 와이파이의 태블릿·휴대폰에서 http://<PC의 IP>:5173
```

### (2) 발표·시연용 — ZIP을 풀고 index.html 더블클릭

```bash
npm run build:zip      # dist-zip/deaf-checkup-sign-questionnaire-demo.zip 생성
```

* ZIP을 풀면 `index.html` 한 개와 `HOW-TO-START.txt`만 들어 있습니다.
* `index.html`을 더블클릭하면 **인터넷 연결 없이** 바로 실행됩니다. 수어영상 3편이 파일 안에 들어 있습니다.
* ZIP 안의 파일명은 모두 영문입니다. 한글 파일명은 Windows 탐색기에서 깨질 수 있어 쓰지 않았습니다.
* 저장소에 미리 만들어 둔 결과물: `demo/index.html`, `demo/deaf-checkup-sign-questionnaire-demo.zip`

### (3) 웹 배포 — GitHub Pages

push하면 `.github/workflows/deploy-checkup.yml`이 실행됩니다.

* `build` 잡: 타입검사 → 단위테스트 → 빌드 → 배포용 ZIP 생성.
  ZIP은 Actions 실행 화면의 **Artifacts → `deaf-checkup-sign-questionnaire-demo-zip`** 에서 내려받습니다.
  Pages 설정과 무관하게 항상 동작합니다.
* `deploy` 잡: `checkup/dist`를 GitHub Pages로 올립니다.

> **최초 1회 수동 설정이 필요합니다.**
> 저장소 **Settings → Pages → Source 를 `GitHub Actions`** 로 바꾸세요.
> 워크플로가 자동으로 켜려고 시도하지만, Actions 토큰에는 Pages 생성 권한이 없어
> `Create Pages site failed. Resource not accessible by integration` 으로 실패합니다.
> 설정 후 Actions에서 워크플로를 다시 실행하면 `https://sunnworks.github.io/claudeworks/` 로 열립니다.

## 4. 화면 설계 원칙 — 수어가 먼저

**농인에게는 수어가 곧 자막입니다. 글자는 오히려 헷갈립니다.** 이 원칙으로 화면을 짰습니다.

1. **수어영상이 화면에서 가장 큽니다.** 모든 화면 맨 위, 단일 컬럼 가운데 정렬.
   높이는 데스크톱 40vh, 모바일 31vh로 제한합니다. 질문과 선택지가 스크롤 없이 함께 보여야 하기 때문입니다.
   (E2E가 360×740에서 첫 선택지까지 화면 안에 들어오는지 검사합니다.)
2. **질문 문장 바로 밑에 선택지가 옵니다.** 사이에 설명 상자를 넣지 않습니다.
3. **글자는 최소로.** 설명이 필요한 것은 `이게 무슨 말인가요?`로 접어 둡니다.
4. **문구는 사용자 말투로.** 개발·행정 용어를 쓰지 않습니다. 예: `필수문항 8/36` → `8 / 36`,
   `제출되지 않았습니다` → `이 내용은 저장되지 않습니다`.
5. **수어 버튼은 아이콘 하나**(손 모양)입니다. 문장마다 붙기 때문에 글자를 넣으면 화면이 시끄러워집니다.
   버튼 이름은 `수어로 보기: <문장>`으로 스크린리더와 툴팁에 전달합니다.

### 수어영상 제공 범위

모든 화면(시작·시나리오·작성자·안내·문항·검토·확인표)에 수어영상 패널이 있습니다.
문항 본문 · 쉬운 설명 · 도움말 · 각 선택지 · 표의 각 행과 열 · 안내문마다 수어 버튼이 붙습니다.

* **자동재생**: 화면이나 문항이 바뀌면 자동으로 재생합니다(기본 켜짐).
  영상에 소리가 없어 브라우저 자동재생 정책에 걸리지 않습니다. `설정 → 자동재생 끄기`로 끌 수 있습니다.
  설계서 13의 "영상 자동재생 금지"는 소리 있는 매체를 전제한 조항이므로, 무음 영상 + 상시 정지 버튼 +
  끄기 설정으로 대체했습니다.
* **순서대로 보여주기**(기본 켜짐): 한 문항을 열면 **질문 → 쉬운 설명 → 선택지 하나씩** 이어서 재생합니다.
  영상 오른쪽 위 점으로 몇 번째인지 알리고, 선택지 차례에는 **그 선택지가 화면에서 강조**됩니다.
  영상이 끝나면 다음으로 넘어가고, 영상을 못 불러오면 1.5초 뒤 넘어가 순서가 멈추지 않습니다.
  `설정 → 순서대로 보여주기 끄기`로 끌 수 있습니다. 순서 구성은 `src/domain/signPlaylist.ts` 에 있습니다.
* **자막**: 영상 바로 아래 띠로 붙입니다. 영상 위에 겹치면 수어 동작을 가립니다.
  지금 무엇을 보여 주는지 **언제나** 알 수 있도록 모든 단계에서 표시합니다.
  `설정 → 자막 끄기`로 끌 수 있습니다.
* **영상 폭은 아래 작성 칸과 같습니다.** 문항이 바뀌어도 크기가 흔들리지 않습니다(E2E 검사).

  | 화면 | 기본 | `화면 크게` |
  | --- | --- | --- |
  | 데스크톱 | 16:9 · 높이 최대 43vh | **1:1 정사각형** · 최대 74vh |
  | 모바일(≤720px) | 4:3 · 높이 최대 26vh | 1:1 정사각형 · 최대 62vh |

  `화면 크게`는 폭은 그대로 두고 세로를 키워 **원본의 좌우 검은 여백만 잘라** 아바타를 크게 만듭니다.
  가로세로비를 16:9(1.78)보다 작게만 두면 **세로는 절대 잘리지 않습니다.**
  수어는 손이 움직이는 공간이 의미를 가지므로 **동작이 잘리는 확대는 하지 않습니다.**
  높이 제한은 질문과 첫 선택지가 아래 버튼 막대에 가리지 않고 함께 보이도록 정한 값입니다(E2E 검사).
* 조작 막대 한 줄: 재생·정지 / 다시 / 배속(1·0.75·0.5) / 전체화면 / 설정.

### 샘플영상

문항별로 검수 완료된 한국수어 영상이 아직 없으므로, 실제 촬영된 **샘플영상 8편을 무작위로 재생**합니다.

| 파일 | 형식 |
| --- | --- |
| `ksl-sample-01~03.mp4` | H.264 MP4, 1920×1080, 무음 |
| `ksl-sample-04~08.webm` | VP9 WebM, 960×540, 무음 |

* 이 데모는 농인 당사자에게 직접 보여 주는 화면이 아니라 검토용이므로, 화면에 `데모`·`샘플영상` 배지를
  띄우지 않습니다. 대신 이 문서와 README 로 한계를 명시합니다.
* 실서비스에서는 문항·선택지·안내문마다 **131문항 × (문항 1 + 선택지 n + 도움말 1)** 규모의 영상이 필요합니다.

### 실제 수어영상으로 교체하는 방법

1. 검수 완료(approved) 영상을 `public/sign-samples/` 에 넣습니다. 예: `ksl-gen-smk-01-v1.mp4`
2. `src/data/signAssets.ts` 의 `APPROVED_SIGN_ASSETS` 에 문항의 `signAssetId` → 파일명을 등록합니다.

```ts
export const APPROVED_SIGN_ASSETS: Record<string, string> = {
  'ksl-gen-smk-01-v1': 'ksl-gen-smk-01-v1.mp4',
};
```

3. 등록된 문항은 무작위 샘플 대신 그 영상을 재생하고, 샘플 배지가 사라집니다.
4. 외부 CDN 주소를 쓰려면 `resolveSignVideoUrl()` 한 함수만 고치면 됩니다.

## 5. 모르는 문항 처리 · 화면 보기 설정

### 공식 응답에 '모름'이 없는 문항

공식 문진표에 `모름`이 없는 문항에 임의로 `모름` 선택지를 추가하면 병원·공단으로 가는 데이터가 오염됩니다.
그래서 설계서 8의 규칙대로 **값을 저장하지 않는 별도 상태**로 처리합니다.

* 공식 응답에 모름이 있는 문항(가족력 5개, B형간염, 구강 2개, 암 가족력, 여성 암문항 등)은 **그 선택지를 그대로** 씁니다.
* 없는 문항에는 **`잘 모르겠어요` 버튼**이 나옵니다. 누르면 답변 값은 만들지 않고 *의료진 확인 요청* 표시만 남깁니다.
* 표시한 문항은 완료를 막지 않으며, 검토 화면과 확인표에 `잘 모르겠음 · 의료진 확인 요청`으로 모아 보여 줍니다.
* 나중에 답을 고르면 표시는 자동으로 사라집니다.

### 저시력 사용자를 위한 화면 설정

화면 위 도구막대에서 바로 바꿀 수 있고 **즉시 전체 화면에 적용**됩니다.

| 설정 | 값 | 구현 |
| --- | --- | --- |
| 글자 크기 | 보통 16px · 크게 19px · 더 크게 22px | `html` 루트 글자 크기를 바꾸고 본문은 rem 기준이라 함께 커집니다 |
| 고대비 | 켜기 / 끄기 | 검은 배경 + 흰 글자 + 노란 강조, 테두리 2px로 색 외에도 구분 |

이 두 설정만 브라우저에 기억합니다(`localStorage`의 `ksl-display-font`, `ksl-display-contrast`).
**건강 답변은 어떤 저장소에도 저장하지 않습니다.** E2E로 검증합니다.

## 6. 검진지원 문항을 묻는 이유

검진지원(SUPPORT) 9문항은 **국가건강검진 공식 문진표가 아닙니다.**
국립재활원 장애친화 건강검진 교육과 동남권원자력의학원 장애친화 검진 사전 체크리스트를 참고한 **서비스 확장 문항**이며,
용도는 하나입니다 — 검진기관이 **방문 전에** 수어통역·동행 허용·보조인력 배치를 준비하게 하는 것.

* 문항 화면 상단에 이 근거와 용도를 그대로 표시합니다.
* 답변은 확인표의 **검진기관 준비사항** 목록으로 출력됩니다 (`src/domain/facilityChecklist.ts`).
* 공식 문진 응답값과 섞지 않습니다(설계서 부록 A).
* 선호 의사소통 방법은 `SUP-05`·`SUP-06`에서 수어영상과 함께 묻습니다. 작성자 설정 화면에서 중복해 묻지 않습니다.

## 7. 문항 데이터 수정 방법

문항은 UI에 하드코딩하지 않고 버전된 데이터 파일로 분리했습니다.

```text
src/data/questionnaire.v2026.ts   모듈 구성·시나리오·서식 버전
src/data/modules/support.ts       검진지원 9문항        (부록 A)
src/data/modules/general.ts       일반 건강검진 35문항  (부록 B)
src/data/modules/oral.ts          구강검진 15문항       (부록 C)
src/data/modules/cancer.ts        암검진 15문항         (부록 D)
src/data/modules/older.ts         노인기능 10문항       (부록 E)
src/data/modules/kdsq.ts          KDSQ-C 15문항        (부록 F)
src/data/modules/phq9.ts          PHQ-9 9문항          (부록 G)
src/data/modules/cape15.ts        CAPE-15 15문항       (부록 G)
src/data/modules/lifestyle.ts     담배사용 평가 8문항   (부록 H)
```

* 공식문구(`officialText`)는 서식 원문입니다. **임의로 바꾸지 마세요.**
* 쉬운 설명(`easyText`)은 서비스 기획 문구입니다. 검증형 척도(KDSQ-C·PHQ-9·CAPE-15)에는 넣지 않습니다.
* 문항 수를 바꾸면 `src/tests/questionnaireData.test.ts` 의 기대값도 함께 고쳐야 합니다(서식 개정 감지용).
* 분기 조건은 `eligibility` 규칙으로 적습니다. 예: `{ type: 'answerEquals', questionId: 'GEN-SMK-01', value: 'Y' }`

### 영상 재생을 안정적으로 만든 방법

영상이 자주 끊기고 "영상을 보여 드리지 못했습니다" 가 뜨던 문제를 다음과 같이 잡았습니다.
고치기 전으로 되돌리지 마세요.

* **영상 요소를 다시 만들지 않습니다.** 한 번만 만들고 `src` 만 바꿉니다.
  요소를 매번 새로 만들면 재생 요청이 서로를 끊어 `play() interrupted` 오류가 나고 순서 재생이 멈춥니다.
* **`play()` 실패를 오류 화면으로 바꾸지 않습니다.** 다른 재생이 끼어든 정상 상황일 수 있습니다.
  실제 미디어 오류(`video.error` 가 있는 `error` 이벤트)만 대체화면을 띄웁니다.
* **멈춤 감시**: 재생도 오류도 없이 5초가 지나면 다음 순서로 넘어갑니다.
* **오류 시 진행**: 영상을 못 불러오면 1.5초 뒤 다음 순서로 넘어갑니다.

## 9. 점수와 안전 처리

| 도구 | 계산 | 의료진 확인 플래그 |
| --- | --- | --- |
| PHQ-9 | 9문항 각 0~3, 총 0~27 | 총점 10 이상 **또는** 9번 문항 1 이상 |
| CAPE-15 | 빈도·고통 각 0~3, 각 총 0~45 | 빈도 또는 고통 총점 6 이상 |
| KDSQ-C | 15문항 각 0~2, 총 0~30 | 총점 6 이상 |

* PHQ-9 9번 문항에 1점 이상 답하면 **다음 버튼보다 먼저** 안전안내가 표시됩니다.
  안내에는 119 또는 112, 자살예방상담전화 109가 들어갑니다.
* 사용자에게 진단명이나 확정 판정을 보여주지 않습니다. 점수는 의료진 확인 플래그 생성에만 씁니다.
* CAPE-15는 빈도가 '없음'이면 고통을 묻지 않고 0으로 계산합니다.

## 10. 개인정보 안전선

* 실명·주민등록번호·전화번호를 입력받지 않습니다.
* 서버와 데이터베이스가 없습니다. 답변은 React 메모리 상태로만 존재합니다.
* `localStorage`, `sessionStorage`, URL, 콘솔 로그, 분석 이벤트에 건강답변을 남기지 않습니다. (E2E로 검증)
* `localStorage`에는 글자 크기·고대비 설정 두 값만 들어갑니다. E2E가 그 두 키 외에는 아무것도 없음을 확인합니다.
* 확인표는 화면과 브라우저 인쇄로만 제공합니다. 파일 다운로드를 만들지 않습니다.

## 13. 수어 촬영 대본 추출

화면에 나오는 모든 문장을 촬영 단위로 뽑아 엑셀로 만듭니다.

```bash
npm run export:sign     # scripts/out/수어촬영대본.xlsx 생성 (python3 + openpyxl 필요)
```

* 같은 문장은 **한 번만** 나옵니다. 어디에 쓰이는지는 `사용 위치` 칸에 모읍니다.
* 선택지는 **단어 중심**으로 뽑고, 고르는 방법은 따로 `응답안내` 문장으로 만듭니다.
  예: `'진단받음', '현재 약물치료 중' 중에서 해당하는 것을 모두 골라 체크해 주세요.`
* 촬영 ID 규칙: `Q` 문항 · `E` 쉬운설명 · `H` 도움말 · `A` 응답안내 · `C` 선택지 ·
  `R` 표항목 · `G` 화면안내 · `B` 버튼 · `S` 안전안내
* 시트 3개: `촬영대본`(전체 목록·필터 포함) · `구분별 요약` · `촬영 안내`
* 추출 규칙은 `src/tools/signFilmingScript.ts` 에 있고 단위테스트로 지킵니다.
  화면 문구를 고치면 같은 파일의 `SCREEN_TEXTS` 도 함께 고쳐야 합니다.
